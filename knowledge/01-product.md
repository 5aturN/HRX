# 01 — Продукт и процессы

## Что за проект

«Склад Гидробот» — Telegram Mini App для склада производственного предприятия (манипуляторы, захваты, R&D).
Сборщики и кладовщики работают с телефонов (Android/iOS) прямо внутри Телеги. Сервер — Windows Server, база — SQLite.
Офлайна нет: без сети не работает.

Боль: около 200 наименований, учёт в голове и бумажках, непонятно чего не хватает, детали теряются между поставкой и сборкой.
Решение: приёмка с фото УПД → остатки с фотками → сборка по составу в один тап → уведомления закупщику → отчёты.

## Кто пользуется

| Роль | Что делает | Что видит |
|---|---|---|
| worker (сборщик/кладовщик) | приёмка, сборка, брак, возврат, выдача в проект, остатки, отчёты | всё кроме админки |
| purchaser (закупщик) | только смотрит остатки и получает письма «закажи» | остатки, отчёты, уведомления в личку |
| admin | всё + люди, составы, папки проектов, пороги, журналы | всё + вкладка «Люди» |

У человека может быть несколько ролей сразу (таблица `user_roles`). `admin` проходит любую проверку.
Регистрация: человек заходит → статус `pending` → вводит ФИО и должность сам → админ проверяет, выдаёт роли, жмёт «Активировать». До этого закрыто.

## Процесс 1. Приёмка

Кладовщик открывает «Приёмка»: вбивает поставщика, № УПД (можно позже — придёт по ЭДО), № счёта, дату.
Дальше строки, каждая — плюсиком:

- **Деталь (наша)**: артикул, название, децимальный номер (обязательно — это наш внутренний номер разработанной детали), папка, кол-во.
- **Покупнина**: выбирает код из каталога (DIN912, ISO7380, LOCTITE243...) — название и фото подтягиваются сами. Руками только размер в артикуле (М6х20) и кол-во.

Шапка одна на всех (поставщик/УПД/дата общие), строки разные. № счёта НЕ уникален: возврат на доработку и повторная приёмка могут идти с тем же счётом — дублей не плодим, просто плюс к остатку.
Повтор того же артикула = плюс к остатку существующей позиции, новой строки в справочнике нет.
К поставке крепятся документы: УПД (оригинал, многостраничный PDF или фото), счёт, транспортная бумажка. Типы: `upd | invoice | transport | other`, до 10 МБ каждый. УПД необязательна для закрытия приёмки. Скачивание нужно.
Фото позиции можно приложить сразу к строке (с телефона) или позже. Если своего фото нет, а код каталога есть — показывается фото эталона.

Файлы: `backend/routers/receipt.py` (эндпоинты), `backend/services/receipt.py` (логика `create_supply`), `frontend/pages/ReceiptPage.tsx`, выбор стандарта — `frontend/components/StdPicker.tsx`.

## Процесс 2. Хранение

Дерево папок — «где лежит»:

```
Склад
├── Серийная продукция → Изделие А, Изделие Б, Изделие В (внутри детали каждого)
├── Расходники → Метизы, Химия, Клеи, Прочее (это и есть «общий стандартный пул»)
└── R&D проекты → Проект Альфа, ... (админ создаёт папку под каждый проект)
```

Каждая позиция лежит строго в одной папке. Детали серийной продукции — с децимальным, расходники — без.
Остаток — одно число `items.qty` (общая масса). Из какой партии списали — не отслеживаем: история приходов хранится, но списание всегда из суммарной кучи. Так решили сознательно: по деталям всё равно непонятно как давно заказали.
Дерево отдаёт `GET /api/folders/tree` (папки + счётчики позиций/штук + флаг фото), страница — `frontend/pages/WarehousePage.tsx`.

## Процесс 3. Сборка серийная (умная, вариант Б)

Сборщик открывает «Сборка»: список изделий и подсборок с фото и остатками. Выбирает, видит состав (что надо / что есть, зелёное/красное) + химию-пометку с фото банки.
Жмёт «Проверить» → бэк говорит: можно или нет, чего не хватает, какие подсборки дособрать (кнопки «Дособрать: ...» прямо там).
Важно: приложение само ничего не дособрает молча — пока человек физически не собрал подсборку и не нажал, верхнее изделие не трогаем. Так избегаем «сборки на бумаге».
Жмёт «Собрать» + кол-во (можно N штук, не только 1): одна транзакция — готовые подсборки минусуем, листья минусуем, изделие плюсуем, двигаем заказ. Не хватило — откат всего и список недостач, частичная сборка запрещена.
После сборки проверяем пороги: что упало ниже — пишем закупщикам + копия админу. На движение пишется версия состава (`bom_version`), старые сборки при правке состава не пересчитываются.
Готовые изделия А/Б/В лежат на складе как обычные позиции с остатком. Подсборки тоже stockable: собираются отдельной кнопкой (списали наполнение, +1 себе).
Кольцо в составе (А в Б, Б в А) ловим и отказываем.

Файлы: `backend/services/assemble.py` (`check_assemble`, `do_assemble`, `_expand`), `backend/routers/assemble.py`, `frontend/pages/AssemblePage.tsx`.

## Процесс 4. R&D проекты

Админ создаёт папку проекта в «R&D проекты». Приёмка с `target=project` кладёт заказные детали в пул проекта (движение `vydacha_rd`).
Выдача: страница «Брак и возврат» → найти → выбрать проект → «Выдать в проект». Стандарты (метизы и пр.) списываются из общей массы с меткой проекта, заказные — из пула проекта. Назад не возвращаются.
Эндпоинты: `GET/POST /api/projects`, `POST /api/to-project`.

## Процесс 5. Брак

Найти позицию → кол-во → причина (обязательно, без неё отказ) → «В брак». Минус из общей массы, движение `brak`, запись в аудит. Больше остатка — отказ. Проверка порога после.

## Процесс 6. Возврат

Ошиблись списанием — найти → кол-во → «Вернуть на склад». Плюс к остатку, движение `vozvrat`. Проверок «а столько ли списывали» нет — любое кол-во.

## Процесс 7. Пороги и уведомления

У каждой позиции `threshold` + галочка `notify_enabled`. Базово стоят на всех расходниках/метизах (20), на любую деталь ставятся руками.
После каждого минуса (сборка, брак, выдача, химия) проверяем: остаток <= порога → шлём всем с ролями `purchaser` + копия `admin` через Bot API: артикул, название, остаток, порог.
Без токена — пишем текст в лог. Тестовые юзеры (tg 1, 2) пропускаются. Повторные письма гасит флаг `low_notified`: одно письмо до пополнения (приёмка на склад сбрасывает, приёмка в проект — нет). Правит пороги только админ: `POST /api/items/{id}/threshold`.
Файл: `backend/services/moves.py` (`notify_low`).

## Процесс 8. Люди и доступы

Вкладка «Люди» (только админ): заявки `pending` отдельно, активные отдельно. Активация с выбором роли (worker/purchaser/admin), блокировка одной кнопкой. Всё пишется в аудит.
Кабинет: аватар (с телефона), имя, должность, роли, статус, мои движения за неделю. Аватар жмётся до 256px.
Эндпоинты: `GET /api/users`, `POST /api/users/{id}/activate`, `POST /api/users/{id}/block`, `GET /api/me`, аватары в `routers/photos.py`.

## Процесс 9. Отчёты

Страница «Отчёты»: фильтр по датам (от/до) → лента движений (дата, тип русским, артикул, кол-во) → кнопка Excel.
Excel (`GET /api/report/excel`): лист «Остатки» (Артикул, Наименование, Децимальный, Папка, Остаток, Порог, Статус) на сейчас + лист «Движения» (Дата, Тип, Артикул, Наименование, Кол-во, Причина, Инициатор, Заказ) за период, до 5000 строк. Шапки русские.
Движения без Excel: `GET /api/moves` с фильтрами. Админский журнал действий: `GET /api/audit` (только админ).
Файлы: `backend/services/reports.py`, `backend/routers/admin.py`, `frontend/pages/ReportsPage.tsx`.

## Процесс 10. Заказы

Заказ = покупатель + строки (изделие, надо, готово) + статус. Создать может любой (разделение прав отложили). Правится по ходу. Резерва деталей нет — только прогресс.
Статусы: Новый → В работе → Готов → Отгружен, кнопки на карточке. В отгруженный собирать нельзя.
Первый пункт всегда «Просто на склад» (теневой заказ, `order_id = NULL`). Сборка в заказ двигает `done_qty`. Прогресс-бар на карточке.
Пример в сидах: «3 манипулятора (А) + 2 захвата (В)». Файлы: `routers/admin.py` (заказы там же), `pages/OrdersPage.tsx`.

## Процесс 11. Каталог стандартов (фото-подстановка)

См. главу 06. Коротко: код DIN/ISO/ГОСТ → название + одно фото на всех. В приёмке выбор с картинками, в сборке банка видна сразу.

## Процесс 12. Избранное

Звёздочка на каждой позиции в складе. У каждого пользователя своё (таблица `favorites`). Страница «Избранное», на главной виджет из 5 частых. Тумблер одним эндпоинтом `POST /api/favorites/{id}`.

## Процесс 13. Химия отдельно

В составе — только пометка (не списывается). Учёт — ручное списание тюбика при выбрасывании (`POST /api/chem-out`, движение `brak` с причиной «Тюбик выброшен»). Порог по штукам. Отдельное меню химии — это фильтр по папке «Химия» + «Клеи».
