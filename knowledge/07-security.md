# 07 — Безопасность

Угроза: склад — деньги. Кто-то outside стучится, кто-то inside сливает. Что сделано и чего не хватает — честно.

## initData (кто стучится)

Каждый запрос несёт `X-Telegram-Init-Data`. Бэк проверяет HMAC-подпись (секрет WebAppData + BOT_TOKEN), свежесть `auth_date` (не старше суток — защита от повторов), достаёт `user.id`. Нет токена / плохая подпись / старое — 401/отказ. Новичок создаётся `pending`, blocked — 403. Тесты: без токена+без DEV отказ, старое отказ, доки закрыты.
DEV_ALLOW_UNAUTH: в репо False (прод закрыт), в локальном `.env` True (разработка). Тесты ставят переменную сами.

## Роли (что можно)

`need_roles`: admin проходит везде; worker — приёмка/сборка/движения/заказы; purchaser — только чтение+уведомления (на деле эндпоинты чтения открыты всем активным — см. «Дыры»); admin — люди/проекты/пороги/каталог/аудит. Проверка на каждом роуте через Depends. Фронт прячет «Людей» от не-админов только визуально (бэк всё равно проверяет).

## Лимиты и заголовки

RateLimit: 120/мин с IP на `/api/*` (health/ready вне лимита — их дёргает мониторинг), дальше 429. Заголовки на всё: nosniff, DENY, no-referrer, Permissions-Policy, Cross-Origin-Opener-Policy. Swagger/ReDoc/openapi выключены (404). SQL-инъекций нет (ORM + параметры). XSS: имена идут в innerHTML через React (экранирует), этикетка — f-string (только свой админ видит). Пути файлов: сейф-имена, `uploads/` вне web-root (отдаём через FileResponse, не статикой).

## Файлы

Лимит 10 МБ, пустые и не-картинки отбиваем (PIL откроет — иначе 400). Ресайз: позиции 800, аватары 256, JPEG 82. До PIL проверяем пиксели (MAX_IMAGE_PIXELS=40 млн) — бомбы режутся до открытия. Типы документов — белый список. Скачивание только авторизованным.

## Секреты

BOT_TOKEN только в локальном `.env`, в гите его нет (`.env.example` пустой). НО: токен светился в переписке и когда-то в `.env.example` — считается скомпрометированным, отозвать через BotFather `/revoke` и выпустить новый (см. главу 08). База и uploads в гите нет. ngrok-бинарь в `.tools/` вне гита.

## Дыры (что доделать до/после прода)

1. Excel везёт токен в URL (`?init=`) — попадает в историю/прокси. Переделать на blob через fetch с заголовком.
2. Чтение (`stock`, `moves`, `orders`, `tree`, `stats`, `recent`, `catalog`) открыто всем активным — purchaser это ок, но pending закрыт только фронтом? Нет — бэк требует active? Проверяет только blocked! Pending тоже читает. Закрыть: требовать status=active везде кроме /me.
3. Нет CSRF — внутри телеги ок (initData вместо кук), кук нет вообще.
4. Нет бэкапа базы — настроить копию hrx.db раз в день (см. 08).
5. Логи без ротации — ЗАКРЫТО: RotatingFileHandler (5 МБ × 5) + консоль.
6. Уведомления без повторов-защиты — ЗАКРЫТО: флаг low_notified, приёмка сбрасывает при пополнении.
7. Загрузка фото без проверки размера пикселей — ЗАКРЫТО: проверка MAX_IMAGE_PIXELS до PIL.
8. `order_id` с фронта не проверяется на принадлежность — чужой заказ можно двигать знаючи id. Проверять или оставить (внутри свои).
