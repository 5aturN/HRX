# 03 — Бэкенд

FastAPI + async SQLAlchemy. Все ошибки русским текстом, логи INFO/ERROR.

## Папки

```
backend/app/
  core/      — настройки (.env), БД (WAL), проверка initData, логи
  models/    — 18 таблиц (tables.py)
  schemas/   — pydantic: приёмка, сборка, движения
  services/  — приёмка, сборка, движения+уведомления, отчёты
  routers/   — deps (кто ты и твои роли), receipt, assemble, moves, admin
  main.py    — приложение + раздача frontend/dist
```

## Ключевая логика

### Приёмка (`services/receipt.py`)
Шапка + строки. Деталь без децимального — отказ. Повтор sku — плюс к остатку. Пишет `supply_items`, `stock_moves`, `audit_log`.

### Сборка (`services/assemble.py`)
Умная (вариант Б): проверка показывает чего не хватает и какие подсборки дособрать, сама молча ничего не собирает. Сборка — одна транзакция: используем готовые подсборки, листья минусуем, изделие плюсуем, двигаем заказ. При нехватке — откат и список недостач. Кольцо в составе — ошибка.

### Движения (`services/moves.py`)
Брак (причина обязательна), возврат, выдача в проект, химия-тюбики. После каждого минуса — проверка порога и `notify_low()` закупщикам + админу через Bot API. Без токена — пишет в лог.

### Отчёты (`services/reports.py`)
Excel из двух листов: Остатки (на сейчас) и Движения (за период). Шапки русские.

### Доступ (`routers/deps.py`)
`current_user` — по initData, новичок уходит в `pending`. `need_roles(...)` — проверка ролей, `admin` проходит везде.

### Прод-закалка (`main.py`, `core/`)
`lifespan` создаёт `uploads/backups/logs`, на выходе закрывает пул БД. `GET /api/health` (жив) + `GET /api/ready` (200/503 по базе, вне лимита). Лимит пикселей `MAX_IMAGE_PIXELS=40 млн`, ротация логов 5 МБ × 5, лимит 120/мин с IP (health/ready вне лимита). `alembic upgrade head` — миграции 0001..0005_low_notified.
